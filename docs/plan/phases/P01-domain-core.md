Prefixes: `A/` = `android/app/src/main/java/com/apoorvdarshan/calorietracker/`, `I/` = `ios/calorietracker/`, `T/` = `android/app/src/test/java/com/apoorvdarshan/calorietracker/`, `IT/` = `ios/calorietrackerTests/`. A number in brackets is the file's length in lines; read only the named part of a big file. Read the research spec section first, then the reference, then its tests.

## Goal

Every number the product shows comes from pure, clock-free functions in `src/domain/`, unit-tested against the values the research recorded: units and conversions (kcal/kJ, kg/lb, cm/ft-in, ml/fl oz), the nutrient catalogue, day keys and ranges in the local zone, meal times and diary grouping, serving scaling with unknown weights, ingredients, recipe splits and combining, BMR/TDEE and plan maths with exact truncation rules, the lock engine, the AI plan validator, Adaptive cadence, the evidence pack, the weight forecast and the fasting rules. No React, no Dexie, no `Date.now()`: time and locale are parameters.

## Slices and waves

Each slice owns its files; no two slices in a wave touch the same path. A builder takes one slice, runs Read → note → Rewrite → Compare for each task, then the loop until green. The lead lands one commit per slice and writes any deviation back into this file.

- **Wave A:** P01-01, P01-02 (one builder): the shared types and the date functions everyone imports.
- **Wave B:** S1 = P01-03..06 (`src/domain/units/**`, `src/domain/servings/expression*`) · S2 = P01-07, P01-08 (`src/domain/nutrients/**`, `src/domain/meals/**`) · S3 = P01-09..11 (`src/domain/servings/{units,scale,ingredients,recipe}*`, `src/domain/food/combine*`) · S4 = P01-12..16 (`src/domain/goals/**`, `src/domain/profile/**`, `src/domain/adaptive/**`).
- **Wave C:** S5 = P01-17..19 (`src/domain/forecast/**`, `src/domain/trackers/**`), after S2 and S4 land.
