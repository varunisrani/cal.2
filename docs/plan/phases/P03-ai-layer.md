## Goal

One seam for every model call: `src/ai/client.ts` takes a request, resolves the role (vision primary, optional text provider, image and text standbys), prepares images, calls one of three wire adapters with one retry ladder and one overall deadline (D-16.23), re-asks once on a cut-off answer, falls back to the standby on any failure including an answer that fails validation (D-16.22), and returns typed results or one error kind with fixed copy. Our own prompts and reply contract live in `src/ai/prompts/`. Everything is tested with a scripted fake fetch, no keys and no network.

Interop note: vendor wire names (Gemini `generateContent`, OpenAI-compatible `chat/completions`, Anthropic `messages`, their headers and response fields) are third-party protocols: check each against the vendor's current API reference on the build date and spell them exactly as the vendor does (03 §2 lists them). Read the reference's code only for behaviour and edge cases. The model presets are our own curated list (D-16.25), checked against each vendor's public model list on the build date; record that date in the data file.

## Slices and waves

Each slice owns its files; no two slices in a wave touch the same path. A builder takes one slice, runs Read → note → Rewrite → Compare for each task, then the loop until green. The lead lands one commit per slice and writes any deviation back into this file.

- **Wave A:** P03-01, P03-02 (one builder): error kinds and the fake fetch that every other test uses.
- **Wave B:** S1 = P03-05, P03-06 (`src/ai/{transport,deadline,retry}.ts`) · S2 = P03-03, P03-04 (`src/ai/catalog/**`, `src/ai/{settings,endpoint}.ts`) · S3 = P03-07..09 (`src/ai/adapters/**`) · S4 = P03-10..14 (`src/ai/image.ts`, `src/ai/parse/**`) · S5 = P03-15, P03-16 (`src/ai/prompts/**`).
- **Wave C:** P03-17, P03-18, P03-19 (`src/ai/client.ts`, `src/ai/tasks/**`, `scripts/ai-cors-probe.ts`).
