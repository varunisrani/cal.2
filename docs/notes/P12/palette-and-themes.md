What it does (own words): the app gets a new look with orange as its brand. The light theme is
clean white: every surface a person reads on is white, separated by warm grey hairlines and soft
shadows instead of tinted backgrounds, with near-black warm text. The dark theme is a neutral
charcoal (no green in it any more), each layer a step lighter than the one below. A new accent
preset, Orange, comes first in the picker and is the default for a new install and for anyone who
never chose one; the six earlier presets stay as choices after it, and a stored choice is kept as
it is. On light the orange is the brightest one that still carries white text and reads as text on
white at 4.5:1; on dark it is a vivid orange with dark ink. Danger moves to a crimson so it never
reads as the brand, success stays a green, focus a blue that stands apart from orange. The page
colour of each theme feeds the browser bar (`theme-color`), the web manifest, the Android window,
status bar and splash, and Capacitor's WebView background.

Edge cases / failure modes:
- A stored `basil` (or any of the six) keeps showing that preset: the ids stay, only a new one is
  added. An install that never chose an accent has no stored value and now shows Orange.
- An unknown stored accent (old or edited storage) falls back to the default: now Orange.
- Cascade: the Orange block is the first of each theme's accent blocks and also carries `:root`
  (dark) and `[data-theme='light']` (light), so no attribute, or a light page with no accent,
  resolves to Orange and every other preset still wins by order or by its two attributes.
- The light orange sits right at 4.5:1 on white, so it must never be text on a tinted surface: a
  wash under accent words would drop below the floor. Every light surface is white for that
  reason (a tinted page would fail the sweep), and the components keep accent words off the wash
  (the tab bar's label, see `components.md`).
- Text on the segmented control's track (`--line`) and on the wash: muted text must still pass
  4.5:1 on both (axe checks it), so the line colour stays light and the muted grey dark enough.
- Danger and orange must not be confused: danger is a crimson (hue ~350°) on light and a rose on
  dark, well away from the orange's ~23°.
- Before the stylesheet loads, `<meta name="theme-color">` shows the dark page (the default), as
  before; the theme runtime sets it to the theme in use.

Our design differences / decisions:
- All values are ours, picked by computation for contrast (the floors of `contrast.test.ts` hold
  for every theme × preset, no exceptions).
- Every light surface (`--page`, `--card`, `--raised`, `--sheet`) is white, so the brightest
  possible orange can pass on all of them; hierarchy comes from the hairlines, radii and shadows.
- The six earlier presets keep their accent, ink and wash values; their contrast is re-checked on
  the new neutrals.
- The preset is named "Orange" (the owner's word); the Ember preset (a red-orange) stays.
- The Android window, status bar and splash use the dark page colour (the manifest's background),
  colorPrimary and colorAccent the light orange. A light status bar for a light device theme
  (`values-night` pairs) is not in this task: it needs a device to check (follow-up).

## Decisions for the lead

- `src/data/settingsSchema.ts` changed (two lines and a comment), although the brief kept
  `src/data/**` out of this task: the stored `display.accent` accepts only the ids in its own
  list and defaults to its own value, and `settingsSchema.test.ts` requires both to equal
  `ACCENT_IDS` and `DEFAULT_ACCENT`. Without it nobody could store Orange. The tests that read the
  old default (`settingsSchema.test.ts`, `repos/settingsRepo.test.ts`, `hooks.test.tsx`) changed
  one value each (`'basil'` → `'orange'`); so did `src/app/ThemeProvider.test.tsx`,
  `AppPage.test.tsx` and `e2e/settings-data.spec.ts` (three lines: the default accent after
  onboarding and after Erase everything).
- An install that never chose an accent has nothing stored and now shows Orange; a stored choice
  (Basil included) is kept. If the owner wants existing users kept on Basil, that needs a stored
  value written once on upgrade (a data change, not done).
- Light surfaces are pure white; the one exact match with a reference colour literal, kept on
  purpose (see the compare checklist).
- Radii move to 14 / 22 / 28 (P00 had 12 / 18 / 24): the row asks for larger card radii.
- Three new colour roles: `--well`, `--track`, `--knob` (`components.md`).
- Follow-up: the Android status and navigation bars stay charcoal in the light theme. A light pair
  (`values-night/` for dark, light bars with dark icons by day) follows the device's mode, which
  matches the app only while its appearance is System; it needs a device to check.
